## 1. About the Project

**TUMPENG (Tata Ukur Mutu Prestasi dan Evaluasi Nilai Pegawai)** merupakan proyek pengembangan sistem informasi berbasis web yang ditujukan untuk mendukung proses monitoring, pengelolaan data, dan penilaian kinerja pegawai di **Badan Pusat Statistik (BPS) Kota Bogor**.

Proyek ini dikembangkan sebagai bagian dari kegiatan akademik mahasiswa Program Studi Sistem Informasi, Universitas Bina Sarana Informatika (UBSI). Pengembangan sistem didasarkan pada analisis kebutuhan dan proses bisnis dengan mengacu pada sistem existing **ASINAN BOGOR**, yaitu sistem informasi nilai kinerja yang digunakan sebagai referensi dalam memahami proses monitoring dan penilaian kinerja pegawai.

TUMPENG dikembangkan sebagai sistem tersendiri dengan ruang lingkup dan implementasi yang disesuaikan dengan hasil analisis kebutuhan. Sistem ini diharapkan dapat membantu pengelolaan informasi kinerja secara lebih terstruktur, mendukung pemantauan data, serta mempermudah pengelolaan dokumen yang berkaitan dengan evaluasi kinerja pegawai.

Proyek ini mencakup tahapan analisis kebutuhan, perancangan sistem, pengembangan aplikasi, dan pengujian fitur sesuai dengan ruang lingkup proyek.

## 2. Project Background

Pengelolaan monitoring dan penilaian kinerja pegawai membutuhkan informasi yang terstruktur agar data kehadiran, nilai kinerja, dokumen pendukung, dan hasil evaluasi dapat dikelola sesuai dengan kebutuhan organisasi.

Melalui kegiatan Praktik Kerja Lapangan (PKL), dilakukan analisis terhadap sistem existing ASINAN BOGOR untuk memahami proses bisnis, fungsi sistem, serta kebutuhan pengguna. Hasil analisis tersebut menjadi salah satu dasar dalam merancang dan mengembangkan TUMPENG.

Pengembangan TUMPENG berfokus pada penyediaan modul-modul yang mendukung pengelolaan kehadiran, penilaian kinerja, dokumen SKP, monitoring, serta pengelolaan pengguna dalam satu aplikasi berbasis web.

## 3. Project Objectives

Tujuan pengembangan TUMPENG adalah:

1. Mengembangkan sistem informasi monitoring dan penilaian kinerja pegawai berbasis web.
2. Mendukung pengelolaan dan pemantauan data kehadiran pegawai.
3. Memfasilitasi pengelolaan nilai kinerja berdasarkan periode penilaian.
4. Mendukung pengelolaan dokumen Sasaran Kinerja Pegawai (SKP) dan dokumen pendukung evaluasi.
5. Menyediakan fitur monitoring untuk membantu pemantauan status data dan dokumen.
6. Mendukung pengelolaan akun pengguna berdasarkan kebutuhan sistem.
7. Menerapkan hasil analisis kebutuhan ke dalam proses perancangan, pengembangan, dan pengujian aplikasi.

## 4. Scope of the Project

Ruang lingkup pengembangan TUMPENG mencakup modul-modul yang berkaitan dengan monitoring dan penilaian kinerja pegawai.

Ruang lingkup tersebut meliputi:

* Monitoring kehadiran pegawai.
* Pengelolaan nilai penilaian kinerja.
* Pengelolaan dokumen penetapan dan evaluasi SKP.
* Pengelolaan laporan dan dokumen pendukung.
* Monitoring kelengkapan dokumen.
* Pengelolaan angka kredit.
* Pengelolaan pertanyaan dan proses penilaian melalui SIPETER.
* Pengelolaan surat keputusan panitia.
* Pengelolaan akun dan status pengguna.
* Penyediaan halaman bantuan penggunaan sistem.

**Catatan:** Daftar di atas merupakan cakupan modul proyek. Ketersediaan fungsi secara menyeluruh bergantung pada implementasi dan hasil pengujian masing-masing modul.

## 9. Installation Guide

### 9.1. Clone Repository

Buka terminal atau Command Prompt, kemudian jalankan:

```bash
git clone https://github.com/marchodeviano-byte/tikum_Bps.git
```

Masuk ke direktori proyek:

```bash
cd tikum_Bps
```

### 9.2. Install PHP Dependencies

Jalankan perintah:

```bash
composer install
```

Perintah tersebut digunakan untuk memasang dependency PHP berdasarkan konfigurasi Composer proyek.

### 9.3. Configure Environment

Salin file `.env.example` menjadi `.env` apabila file tersebut tersedia di repository.

Pada Windows, file dapat disalin secara manual melalui File Explorer atau menggunakan terminal yang sesuai.

Kemudian buat application key:

```bash
php artisan key:generate
```

### 9.4. Configure Database

Buat database MySQL untuk aplikasi melalui phpMyAdmin, MySQL client, atau perangkat pengelolaan database lainnya.

Sesuaikan konfigurasi database pada file `.env`:

```env
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=nama_database
DB_USERNAME=root
DB_PASSWORD=
```

Ganti `nama_database`, username, dan password sesuai konfigurasi MySQL lokal. Contoh tersebut bukan kredensial produksi.

### 9.5. Prepare Database

Jika repository menyediakan migration yang sesuai, jalankan:

```bash
php artisan migrate
```

Jika aplikasi memerlukan data awal, periksa seeder yang tersedia sebelum menjalankan perintah seeding.

Jika proyek menggunakan database SQL terpisah atau struktur tabel yang belum sepenuhnya tersedia dalam migration, ikuti prosedur penyiapan database yang sesuai dengan repository.

**Penting:** Jangan menjalankan migration atau seeder pada database produksi tanpa pemeriksaan dan pencadangan terlebih dahulu.

### 9.6. Build Frontend Assets

Jika proyek memiliki `package.json` dan menggunakan Vite atau proses build frontend lainnya, jalankan:

```bash
npm install
npm run build
```

Langkah ini hanya diperlukan jika konfigurasi frontend proyek membutuhkannya.

### 9.7. Run the Application

Jalankan server pengembangan Laravel:

```bash
php artisan serve
```

Buka alamat lokal yang ditampilkan di terminal untuk mengakses aplikasi melalui browser.

**Catatan instalasi:** Langkah di atas merupakan panduan umum aplikasi Laravel. File environment, migration, seeder, aset frontend, dan database perlu diperiksa terlebih dahulu agar instruksi final sesuai dengan kondisi repository TUMPENG.

## 14. Repository Guidelines

Untuk menjaga keteraturan pengembangan bersama, setiap anggota tim disarankan untuk:

1. Mengambil source code terbaru sebelum mulai mengerjakan perubahan.
2. Membuat branch tersendiri untuk fitur atau perbaikan yang dikerjakan.
3. Menguji perubahan secara lokal sebelum mengirimkannya ke repository.
4. Menuliskan pesan commit yang menjelaskan perubahan.
5. Menghindari commit file konfigurasi sensitif, password, dan data pribadi.
6. Melakukan pemeriksaan perubahan sebelum menggabungkan branch ke branch utama.

Contoh alur kerja Git:

```bash
git pull origin main
git checkout -b fitur/nama-fitur
```

Setelah melakukan perubahan:

```bash
git add .
git commit -m "Menambahkan fitur yang dikerjakan"
git push origin fitur/nama-fitur
```

Nama branch `main` dapat disesuaikan dengan branch utama yang digunakan repository. Penggabungan perubahan dilakukan setelah pemeriksaan oleh anggota tim.

## 15. Security and Data Privacy

Karena proyek berkaitan dengan informasi kepegawaian, pengembangan dan pengujian perlu memperhatikan keamanan data.

* Jangan mengunggah file `.env` atau kredensial database.
* Jangan menyimpan password dalam bentuk teks biasa.
* Gunakan akun uji dan data dummy saat melakukan demonstrasi.
* Batasi akses data berdasarkan kebutuhan dan kewenangan pengguna.
* Periksa validasi input, otorisasi, dan keamanan unggahan file.
* Hindari mempublikasikan data kepegawaian atau dokumen internal tanpa izin dari pihak berwenang.
* Pastikan repository dan dokumentasi tidak memuat informasi sensitif milik instansi.
